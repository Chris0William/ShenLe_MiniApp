# 04 分阶段实施、指标与回滚

## 1. 总体实施边界

本文是下一轮工作的执行蓝图。除本轮已上传0.4.44外，性能和界面方案均未实施。生产日志读取、结构检查及公开接口探测为只读。

开始开发前：按用户指令处理当前未提交改动，前后端建立对应恢复点和独立优化工作树。不能擅自合并 `feat/source-contact-portal` 到旧主线，也不能将未发布方案文件当作已上线说明。

开发与验证数据库必须为 `adminet_test`，经SSH/容器或测试API访问；不开放公网MySQL。涉及媒体写测试须先核实独立测试前缀/桶。

## 2. 阶段计划

工期为单名熟悉项目开发者的有效工作日粗估，不含微信审核、等待业务决策及第三方故障；是排期参考，不是时限承诺。

| 阶段 | 内容 | 主要交付 | 估算 | 依赖 |
|---|---|---|---|---|
| P0-A | 基线、日志脱敏、成功读日志采样、轮转方案 | 指标、配置差异、轻量回滚、增长报表 | 1–2天 | 确认日志保留与发布窗口 |
| P0-B | 房东读范围、端身份优先级、公共坐标边界、缓存换号隔离 | 权限矩阵与测试库越权回归 | 2–3天 | 多身份优先级确认 |
| P1-A | SysFile索引、关键SQL分支、房源索引验证 | 幂等迁移、EXPLAIN前后、性能样本 | 1–3天 | 测试库具备代表数据 |
| P1-B | 地图轻点、列表分页、摘要查询优化 | 新增轻量API、旧接口兼容、筛选等价测试 | 3–5天 | P0-B、P1-A |
| P1-C | 在途去重、会话缓存、局部刷新、列表锚点 | 请求次数/编辑返回对比 | 2–3天 | 查询契约稳定 |
| P2-A | 共用布局、摘要、媒体和大型页面拆分 | 三端组件规范、分批页面验收 | 4–7天 | P1接口与数据流稳定 |
| P2-B | 上传进度与重试，必要时跨页队列 | 状态机、草稿恢复、真机弱网验证 | 小步2–3天；跨页另3–5天 | 媒体生命周期确认 |
| P2-C | 关键字段版本、冲突检测和审计差异 | 可恢复批次与冲突UI | 3–5天 | 保留周期与恢复权限确认 |

推荐先审批P0和P1-A，观察收益后再做地图及界面较大调整。不要求一次实施完所有阶段。

## 3. 可执行任务清单

| ID | 任务 | 验收条件 | 回滚 |
|---|---|---|---|
| LOG-01 | 请求日志排除认证头、签名参数和Base64 | 日志抽样不含原始敏感凭证，异常可用TraceId追踪 | 恢复原日志配置前保留脱敏规则 |
| LOG-02 | 成功读取采样、限制返回体 | 24小时增长显著下降，错误检索可用 | 恢复采样比例，不恢复敏感正文 |
| LOG-03 | JSON/file/Nginx轮转 | 每种日志有上限且轮转实际发生 | 恢复Compose并验证挂载；历史删除不可当可逆配置操作 |
| AUTH-01 | 统一房东读范围 | 用测试房东访问他人Page/Detail/媒体均被正确拦截 | 开关回退需禁止暴露未授权范围 |
| AUTH-02 | 维护关系/角色变更主动失效 | 去除分配后旧会话立即失去对应写权限 | 回退实现但保留已确认权限语义 |
| CACHE-01 | 换号/登出和在途代号 | 上一账号响应不回填下一账号；旧文件路径失效可重取 | 回退新缓存，使用无缓存正确路径 |
| DB-01 | 媒体关系索引 | 代表查询使用索引，写回归通过 | 仅删除本轮新建索引 |
| DB-02 | 房源复合索引候选验证 | 所选SQL扫描/延迟降低且无写入退化 | 回退新索引，不删既有索引 |
| QUERY-01 | 非距离分页走数据库 | 同条件结果/排序/总数与旧实现一致 | 保留旧分支特性开关 |
| QUERY-02 | 距离查询边界优化 | 位置、半径、边界值和无坐标语义一致 | 回原距离实现 |
| MAP-01 | 轻点位/摘要按需 | 一个map，全部命中语义保留，数据与列表一致 | 旧page模式回退 |
| UI-01 | 列表局部修补与锚点 | 编辑返回值最新，不回顶部，不重拉全部已加载页 | 恢复全量刷新作为已知兼容路径 |
| UI-02 | 页面壳/浮层/摘要统一 | 三端不串权限，无穿透和布局溢出 | 按单页回退，避免全局CSS联动 |
| MEDIA-01 | 单文件进度/重试 | 多选数量一致、失败可见、不重复挂载 | 旧顺序上传路径 |
| DATA-01 | 乐观并发与字段差异 | 两人修改可提示冲突，恢复产生新审计 | 新字段保留，关闭新写策略，旧包仍可用 |

## 4. 测量方案

### 4.1 基线场景

- 游客首次进入：脱敏区域显示、定位授权、地图/列表切换。
- 业务员：无条件首页、租金/区域/类型组合、附近距离、已租不可见、筛选后数量一致。
- 房东：名下1/10/50个楼盘（后两者用测试数据）、楼栋房态、批量经营参数。
- 维护人：受托房源编辑、关系取消后权限失效。
- 管理员/超管：全局地图、长列表第10页编辑返回、批量新增50/200间、更新榜查询。
- 媒体：2个视频、9个混合媒体、长名、大于限制的文件、1条失败后后续继续；iOS和安卓各测。
- 会话：登录、退出、换账号、审批通过、拒绝、停用、角色叠加、扫码冷启动/热启动。

测试数据规模建议：当前约2万房源等价集合；扩展到10万/50万评估趋势。数据只能生成在测试库，不复制生产手机号、身份材料或私人媒体。

### 4.2 指标与目标

| 指标 | 当前证据 | 第一阶段候选目标 |
|---|---|---|
| 常用楼盘列表API P95 | 有限样本约517ms，不是正式基线 | 同场景优化至少30%，目标 <=300ms（同网络/同数据） |
| 地图数据请求 | 每页200条循环到总数 | 约千楼盘时轻点1次；选中后摘要最多1次，非核心异步 |
| 地图轻点体积 | 目前完整列表DTO，无独立值 | 未压缩JSON <=200KB，超预算需明确分页/视野方案 |
| 媒体关系SQL扫描 | 代表EXPLAIN估算23,412 | 跟匹配附属文件数同量级，不再ALL |
| 编辑返回请求 | 随已浏览页数线性增加 | 单项修改通常1次摘要修补，结构变更仅重拉窗口 |
| UI按键反馈 | 未量化 | 100ms内反馈，不用完成网络请求才亮状态 |
| 手机首个有用内容 | 未量化 | 真机4G冷启动目标 <=2s，需拆解微信启动/网络/渲染耗时 |
| 列表滚动 | 未量化 | 无可感知卡顿；渲染窗口有界，内存不随无限翻页持续增长 |
| 日志新增量 | 本轮是容量快照，无每日斜率 | 同流量下技术日志字节数降低80%以上 |
| 权限回归 | 代码已覆盖部分路径，未完整实测 | 测试矩阵全部通过，零跨账号缓存结果 |

收益只在相同数据、设备、网络和缓存条件下比较。不要把冷缓存旧版本与热缓存新版本比较，也不要用服务器本地探测替代用户手机延迟。

### 4.3 负载测试

从测试环境5并发开始，分阶段到20/50，以系统可承受为上限；2核主机与生产共用资源，测试环境压测要有资源限制和停止阈值，不在生产繁忙时直接打满。

记录RPS、P50/P95/P99、错误率、SQL次数、rows examined、CPU、内存、GC、线程池、MySQL锁等待和IO。样本至少覆盖稳定窗口；出现生产延迟上升、持续CPU>80%或剩余内存明显下降立即停止。

## 6. 技术验收与证据

小程序：`pnpm type-check`、影响范围Vitest及必要全回归、定向ESLint、`git diff --check`、BOM扫描。需要产物时按Runbook构建，不留watcher。

后端：原生 `dotnet build/test/publish`，net8.0。DLL被锁时报告文件/PID，不改临时OutDir或私自停进程。

运行验收：测试API真实身份读取及受控写入；开发者工具CDP检查route、返回和数据；iOS/安卓验证选择器、扫码、相册和原生map。浏览器用于Web/H5布局，不能代替微信原生接口验证。

记录每个阶段：分支/提交/未提交补丁、环境、SQL/接口前后指标、截图或录屏、已知问题、回滚点。日志与报告不包含令牌/密码/手机号材料。

本轮没有新运行原型和全尺寸视觉截图；UI文档是待设计验收的结构规范。已有0.4.44只完成二维码位置调整和构建上传。

## 7. 发布与回滚纪律

1. 每个阶段独立恢复点，前后端相关改动保持可对应，禁止一个大提交混入所有重构。
2. 数据库迁移先测试，检查实际已有索引/列，再执行幂等脚本。新增索引与列不默认删除旧结构。
3. 备份受影响程序/配置/必要小业务表；日志不做全量备份，不对整个生产库无差别dump。
4. 先部署兼容旧客户端的后端及迁移，再上传测试/体验包；测试API与生产API不得混淆。
5. 生产发布继续遵循用户流程：小程序审核通过通知 → 后端部署验证 → 用户点击正式发布。
6. 上传严格复用Runbook；一次正常尝试，一次针对原错误诊断后停止；不换私钥/CI方案反复试错。
7. 回滚程序恢复旧DLL或旧前端包；新增兼容字段一般保留。日志历史删除、数据修复和恢复是独立操作，不伪装成普通回滚。
8. Redis/多实例改造前先验证票据、缓存及分布式失效；不能边切缓存边做权限大改。

## 8. 待确认事项

- 数据权限：多身份冲突优先级、旧盘源对接人是否继续独立存在、维护人是否未来自助申请。
- 业务日志：保留年限、是否必须记录原值、谁可恢复、批量恢复上限。
- 列表体验：影响排序的编辑是否立即重排，还是维持锚点直到主动刷新。
- 大规模地图：未来超过轻点预算时可否采用视野加载；当前默认保持全部命中及不合并气泡。
- 后台上传：先做页内进度还是确需跨页面；不承诺操作系统后台存活。
- Web：确认 `/admin` 当前线上构建来源，明确是否把PC批量录入作为同步优化目标。
- 资源：确认可压测时段及测试容器资源限制，避免同机测试扰动生产。

上述问题不会阻止先做日志脱敏、有限指标收集、测试库索引验证和局部反馈优化；涉及业务规则变化的任务等待对应确认。
