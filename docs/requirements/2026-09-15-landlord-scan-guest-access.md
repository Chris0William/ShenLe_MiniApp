## 需求一：房东分享码对游客开放（扫码临时授权）

1. 房东出示二维码后：
   - **已登录游客**：扫码 → 与业务员一样，业务员端自动筛选出该房东名下楼盘（能看到真实楼盘卡片）
   - **未登录**：先弹登录（现有登录弹窗），登录完成后**直接筛选出楼盘，不再跳申请使用页**
2. **临时授权语义**：该可见性由扫码令牌驱动，不是身份升级
   - 退出重进（无令牌）→ 回到脱敏
   - 手动删掉筛选 → 回到脱敏
3. **申请使用流程保持现状**：仍通过点击脱敏内容触发申请，不通过扫码申请
4. 业务员（777+）扫码行为不变

## 需求二：单楼盘二维码

1. 房东端可按**每个楼盘单独**生成二维码（小程序码）
2. 游客/业务员扫码 → 进入只筛选出**这一个楼盘**的数据页面（把"筛选房东全部楼盘"逻辑改为"筛选单楼盘"）
3. 业务员扫单楼盘码 = 单楼盘筛选（正常数据）；游客扫 = 同样进入该楼盘筛选视图（受需求三开关约束）
4. 令牌语义与需求一相同：退出重进/删筛选回到脱敏

## 需求三：楼盘卡片隐私三开关（游客可见性控制）

1. 位置：房东端 → 楼盘信息 → 点楼盘"设置费用"界面，**宠物情况和公告之间**（图1红框处）
2. 三个开关：
   - 租客是否可以看到租金
   - 租客是否可以看到佣金
   - 是否可以看到公告
3. **作用范围**：只控制**游客**在地图、列表中看到的楼盘卡片显示；**不控制业务员**（业务员永远看真实数据）
4. 显示规则：楼盘设置了打开某开关 → 游客端该项显示 `？？？`，例如 `租金：？？？`
5. 存量楼盘默认值需在梳理时确认（倾向：默认不隐藏，不影响现状）
