# 深乐租企业官网设计规格

## 1. 目标

为“深租宝典 / 深乐租”设计一个企业官网，用于对外获客、品牌展示和招商合作。

官网不直接承载房源交易，不展示真实房源明细，不开放敏感数据查询。它的核心任务是让访客快速理解：深租宝典是一套面向二房东、中介门店和区域房源团队的房源数据管理与展示平台，可以帮助团队统一维护房源、快速找房、管理销控、复用媒体资产，并通过权限机制保护数据。

## 2. 目标受众

### 2.1 主要受众

- 二房东团队：关注多区域、多楼盘、多套房源的集中维护效率。
- 房产中介门店：关注快速找房、向客户展示房源、减少人工翻表。
- 区域房源运营团队：关注地图定位、销控状态、媒体资料和团队协作。

### 2.2 次要受众

- 合作伙伴：评估产品是否适合联合运营或区域合作。
- 小程序审核和备案查看方：确认产品是房源信息管理与展示工具，不涉及在线交易、支付或用户自行发布。

## 3. 核心定位

### 3.1 主标语

把分散房源变成可运营的数据资产

### 3.2 副标语

深租宝典为二房东、中介门店和区域房源团队提供楼盘、房源、销控、地图、媒体与权限管理能力，让团队更快找房、更准维护、更安全地展示数据。

### 3.3 一句话介绍

深租宝典是一套面向房源运营团队的小程序化房源管理平台，覆盖楼盘资料、房源信息、地图筛选、销控状态、图片视频媒体池和角色权限管理。

## 4. 信息架构

### 4.1 单页官网优先

第一版建议做单页官网，避免内容过散，便于快速上线、备案展示和后续投放。

页面顺序：

1. 顶部导航
2. 首屏价值主张
3. 平台核心能力
4. 适用场景
5. 数据与权限保护
6. 合作咨询转化区
7. 页脚备案与联系方式

### 4.2 后续可扩展页面

第一版不必实现，但结构预留：

- 产品能力页：展开楼盘、房源、地图、销控、媒体、权限。
- 合作方案页：面向二房东和门店团队介绍合作方式。
- 关于我们页：介绍品牌、服务区域和团队背景。

## 5. 首页内容设计

### 5.1 顶部导航

导航项：

- 产品能力
- 适用场景
- 数据安全
- 合作咨询

主按钮：

- 预约演示

设计要求：

- 桌面端导航固定在顶部或首屏上方。
- 移动端收敛为简洁顶部栏，主按钮保留。
- 不使用过多英文装饰词，保持中文业务表达。

### 5.2 首屏

首屏内容：

- 标签：房源管理 · 地图找房 · 团队协作
- 标题：把分散房源变成可运营的数据资产
- 说明文案：深租宝典为二房东、中介门店和区域房源团队提供楼盘、房源、销控、地图、媒体与权限管理能力，让团队更快找房、更准维护、更安全地展示数据。
- 主按钮：预约产品演示
- 次按钮：查看核心功能

首屏视觉：

- 左侧为价值文案和 CTA。
- 右侧为抽象产品看板，不使用真实房源名称和真实地址。
- 看板可展示楼盘数、房源数、媒体数、地图热力点、销控状态等概念化信息。

### 5.3 核心能力

四个核心能力卡片：

1. 楼盘与房源管理
   - 楼盘、楼栋、房号、户型、租金、状态统一维护。
2. 地图找房与筛选
   - 支持区域、附近距离、租金范围和楼盘名称检索。
3. 销控看板
   - 按楼盘和楼栋查看空置、预定、已租等状态。
4. 媒体资产池
   - 楼盘图片和视频集中管理，房源可复用并设置封面。

辅助能力：

- 微信授权登录
- 游客脱敏预览
- 管理员审批
- 权限变更强制重登

### 5.4 适用场景

场景卡片：

- 二房东多房源运营：减少 Excel 和聊天记录分散维护。
- 中介门店快速找房：通过地图和筛选快速定位可推荐房源。
- 区域团队统一管理：楼盘、房源、媒体和销控形成统一数据底座。

每个场景只讲业务收益，不承诺具体成交结果。

### 5.5 数据与权限保护

强调点：

- 未授权用户只看到脱敏预览，不暴露真实楼盘和房源明细。
- 普通用户通过审核后查看完整房源信息。
- 管理员可维护楼盘、房源、销控、区域和标签。
- 超级管理员负责用户审批、角色调整和用户注销。

禁止展示：

- 真实房源地址
- 真实楼盘坐标
- 房号明细
- 房东电话
- 私有图片或视频原始素材

### 5.6 合作咨询

转化区文案：

- 标题：想把你的房源团队数字化？
- 说明：留下联系方式，获取深租宝典产品演示与合作方案。
- 按钮：立即咨询

第一版表单字段：

- 姓名
- 手机号
- 团队类型：二房东 / 中介门店 / 区域团队 / 其他
- 房源规模：50 套以下 / 50-200 套 / 200 套以上
- 备注

如第一版不接后端表单，可先使用微信二维码或联系电话作为转化入口。

## 6. 视觉方向

### 6.1 总体风格

采用“绿色 + 米色 + 产品看板”的视觉方向，延续深乐租小程序当前的绿色、米色、卡片式气质，但官网要比小程序更开阔、更品牌化。

关键词：

- 专业
- 可信
- 温和
- 数据化
- 房源运营感

### 6.2 色彩

建议色彩：

- 主绿色：#1F7A4C
- 深绿色：#173325
- 浅绿色：#E9F4E5
- 米色背景：#F6F1E8
- 卡片白：#FFFFFF
- 正文灰绿：#52695C
- 强调黄：#FFD166，仅用于地图点或数据强调

### 6.3 字体与排版

中文标题使用较厚重、稳定的黑体风格。

建议：

- 标题：思源黑体 / 阿里巴巴普惠体 / HarmonyOS Sans
- 正文：同一字体家族常规字重
- 避免 Inter、Roboto、Arial 等默认感过强的英文栈作为主要视觉语言。

### 6.4 图形语言

优先使用抽象产品界面和数据图形，不使用真实房源图片作为官网首屏主视觉。

可用图形：

- 地图热力点
- 房源运营看板
- 楼盘卡片
- 销控状态格
- 媒体缩略图占位
- 权限角色节点

## 7. 图片生成要求

可使用 CRS ImageGen 生成一张官网首页高保真概念图，用于确认视觉方向。

生成图要求：

- 类型：企业官网首页高保真视觉稿
- 画幅：横版 1536x1024
- 风格：绿色米色、现代企业官网、产品数据看板、温和可信
- 内容：首屏 + 部分核心能力区
- 不出现真实楼盘名、真实地址、真实房源图片和真实联系方式
- 中文文字只保留少量关键文案，避免 AI 生成大量不可控小字

## 8. 技术实现边界

本规格只定义官网内容和视觉，不直接决定技术栈。

后续实现可选：

1. 独立静态官网
   - 适合最快上线。
   - 可使用 Vite + Vue 或 Astro。
2. 合并进现有前端仓库
   - 便于统一工程，但会和小程序构建混在一起。
   - 第一版不推荐。
3. 后端站点静态托管
   - 可通过 Nginx 静态目录托管。
   - 适合与现有 `shenzuyk.com` 同域部署。

推荐第一版使用独立静态官网，然后通过 Nginx 挂载到 `https://shenzuyk.com/`，API 保持 `https://shenzuyk.com/api/`。

## 9. 合规与表达边界

官网必须避免以下表达：

- 保证成交
- 自动匹配客户
- 官方认证房源
- 免费或价格承诺
- 未经确认的覆盖城市、楼盘数量和房源数量

可使用的稳妥表达：

- 房源信息管理与展示工具
- 团队内部维护
- 地图定位与筛选
- 房源媒体统一管理
- 权限审核后查看完整信息
- 不提供在线交易、支付或用户自行发布

## 10. 第一版验收标准

第一版官网达到以下标准即可进入实现：

- 首屏 5 秒内能理解产品用途。
- 有明确“预约演示 / 立即咨询”转化入口。
- 核心能力覆盖楼盘、房源、地图、销控、媒体、权限。
- 视觉与小程序品牌一致，但更像企业官网。
- 不泄露真实房源数据。
- 移动端可读，不出现横向溢出。
- 后续可扩展产品能力页和合作方案页。
