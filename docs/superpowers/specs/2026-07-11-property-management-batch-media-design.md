# 房源管理链路、批量操作与视频封面设计

## 目标

将管理端房源维护收敛到“楼盘 -> 楼栋 -> 房源”链路，提供适合小程序屏幕的批量新增、选择修改和选择删除能力，解决编辑返回后列表不更新的问题，并停止依赖腾讯云数据万象实时生成视频封面。

## 范围

- 小程序管理端工作台、楼盘管理、楼栋管理、楼栋房源、房源表单和销控相关刷新。
- 后端现有楼栋批量、房源批量、媒体草稿和媒体挂载接口的兼容性补充。
- 视频缩略图上传、持久化关联、媒体复制和输出。
- 不改匿名预览、用户端找房筛选、扫码登录和权限角色模型。

## 管理链路

写操作统一从以下路径进入：

```text
楼盘管理 -> 楼栋管理 -> 楼栋房源 -> 新增 / 编辑 / 批量管理
```

- 工作台移除“房源管理”和“发布房源”快捷入口。
- 底部“房源”页保留查询能力，移除全局新增入口；管理员点击楼盘时进入该楼盘的楼栋管理。
- 楼栋卡片进入房源页时传递楼盘和楼栋 Id、名称。
- 新增房源必须具备楼盘和楼栋上下文。
- 编辑房源只读显示楼盘、楼栋和楼栋总楼层；普通更新不改变归属。

## 一键创建楼栋

- 指定楼盘的楼栋为空时显示“一键创建楼栋”。
- 名称使用楼盘名称，复用现有 `/api/slBuilding/add`。
- 提交期间禁用按钮；成功后刷新当前列表；并发重名时重新加载已有楼栋。
- 普通新增楼栋入口保留。

## 楼栋房源与批量操作

楼栋房源页以 `buildingId` 为固定范围。页面默认是普通浏览模式，右上角“批量管理”进入选择模式，卡片显示复选框，底部工具栏提供修改和删除；批量新增不需要先选择房源。

### 批量新增

- 输入起始楼层、生成楼层数、每层房间数和可选单元号。
- 房号由楼层和两位房间序号组成，例如 `101`、`102`、`201`、`1001`。
- 实时预览首批房号、总数量和重复房号。
- 新房源默认标题等于房号、租金为 `0`、状态为 `3=下架`，默认户型沿用单条表单初始值。
- 若生成的最高楼层超过楼栋总楼层，先更新楼栋总楼层，再提交批量新增。
- 后端批量预检失败时不写入任何房源；成功后返回创建数量。

### 批量修改

- 先读取 `/api/slProperty/batchList` 完整快照。
- 表单中的每个可批量字段都有显式启用开关；未启用字段保持快照原值。
- 可修改租金、面积、户型、状态、朝向、装修、出租方式、押付方式、最短租期、联系人、描述、备注、标签、设施和媒体。
- 不批量修改楼盘、楼栋、楼层、房号和标题。
- 前端将启用字段合并到每条完整快照，再调用现有 `/api/slProperty/batchUpdate`，兼容当前完整更新契约。
- 文本清空通过启用字段并提交空值表达；数值 `0` 与未修改严格区分。

### 批量媒体

- 媒体修改未启用时保持每套房源原媒体。
- 支持追加和替换；清空是单独的危险操作。
- 来源统一为“从楼盘选择”或“上传媒体”。
- 楼盘媒体由后端为每套房源复制 `SysFile` 记录，不移动源媒体。
- 同一批次上传的草稿媒体允许挂载到多个房源；后端必须为后续房源复制媒体，而不是重复抢占同一草稿记录。

### 批量删除

- 只允许选择当前楼栋房源。
- 二次确认展示数量和部分房号。
- 调用 `/api/slProperty/batchDelete`，事务失败时不删除任何一条。
- 成功后本地移除列表项并更新统计。

## 媒体入口

房源表单不再同时显示两个顶部按钮和一个网格入口。媒体网格只保留“添加媒体”入口，点击后由 `wd-action-sheet` 提供“从楼盘选择”和“上传媒体”。单条和批量表单复用媒体来源选择逻辑。

## 返回刷新

新增轻量实体变更中心，记录楼盘、楼栋和房源的最近变更及版本号。

- 单条编辑成功后发布带房源 Id 的 `updated` 事件。
- 来源列表在恢复显示时只重新读取并替换该房源，不重置分页和滚动位置。
- 删除成功后直接移除本地项。
- 批量新增、删除等结构变化重新读取当前已加载范围，并在 DOM 更新后恢复 `scrollTop`。
- 工作台统计、楼盘房源数、楼栋房源数和销控只在对应版本变化时刷新。
- 页面销毁时解除事件监听，避免重复处理。

## 视频封面

### 立即止损

- 删除所有 `ci-process=snapshot` URL 拼接。
- 没有持久化缩略图的视频显示稳定的视频占位块和播放图标。
- 点击视频仍使用现有弹层播放器。

### 新视频

- `wx.chooseMedia` 返回视频时读取 `thumbTempFilePath`。
- 视频和缩略图都作为普通文件上传；缩略图标记为 `image:video_poster`。
- 新增 `/api/slMediaDraft/bindPoster`，校验两个文件属于当前用户草稿后，将缩略图关联到视频文件。
- 采用 `SysFile.BelongId = videoFileId` 表达缩略图从属关系，因此缩略图不会出现在楼盘或房源媒体列表中，也不修改 `ShenLe.Core` 实体。

### 复制与输出

- 媒体从楼盘复制到房源时，同时复制其缩略图 `SysFile` 记录并改为从属于新视频文件 Id。
- 媒体输出增加 `posterFileId` 和 `posterUrl`；列表视频封面增加 `coverPosterFileId` 和 `coverPosterUrl`。
- 小程序优先通过 `posterFileId` 下载私有缩略图；没有缩略图时使用占位块，绝不回退数据万象。

### 存量回填

- 本轮先完成协议和新上传链路。
- 存量视频后续由可断点续跑的本地 FFmpeg 工具抽取约第 1 秒画面并绑定；回填失败不影响视频播放。

## 权限与兼容

- 单条新增、更新、删除继续使用原有楼盘房东或管理员权限。
- 管理端批量接口继续要求管理员。
- 房东在自己楼盘内编辑房源时，仍允许从该楼盘媒体池复制媒体；不得复制其他楼盘媒体。
- 现有单条 API 路径、字段和返回保持兼容，只增加可选视频缩略图字段。
- 现有没有缩略图的媒体、没有楼栋总楼层的历史数据均可正常读取。

## 验收

- 空楼盘一键创建同名楼栋。
- 楼栋范围内生成房号、批量修改和批量删除均具备明确预览和事务结果。
- 编辑深层列表项返回后卡片更新，页面不跳到顶部。
- 房源表单不能修改所属楼盘、楼栋和总楼层。
- 媒体入口无重复，上传和楼盘选择均可用。
- 编译产物不包含 `ci-process=snapshot`。
- 新上传视频具备持久化缩略图；无缩略图视频显示占位且可播放。
