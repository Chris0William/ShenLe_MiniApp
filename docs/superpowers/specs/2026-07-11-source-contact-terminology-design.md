# 盘源对接人术语统一设计

## 目标

将当前产品中面向用户的“房东”身份统一定义为“盘源对接人”，删除“二房东”定位，并移除小程序房源级联系人信息。权限规则、数据库结构和现有 API 契约保持兼容。

## 术语规则

- 身份名称统一为“盘源对接人”。
- 端名称统一为“盘源对接人端”。
- 管理入口统一为“盘源对接人管理”。
- 用户操作统一为“申请成为盘源对接人”。
- 官网受众文案使用“盘源对接人、房源门店和区域房源团队”。
- 官网运营场景使用“盘源规模化运营”，不使用“二房东”。

## 小程序改动

### 身份与申请

- 用户端申请入口、申请状态和提示改为“盘源对接人”。
- 管理端的申请审批、直接设置、取消资格、分配楼盘等文案改为“盘源对接人”。
- “房东端”“房东中心”等页面标题改为“盘源对接人端”“盘源对接人中心”。
- 路由拦截提示和角色展示同步使用新术语。

### 房源级联系人

盘源对接人是楼盘归属角色，不再作为每套房源上的联系人字段展示或编辑。

- 房源新增/编辑表单删除联系人姓名和联系电话输入项。
- 房源详情删除“联系房东”按钮及拨号逻辑。
- 房源批量修改删除联系人姓名和联系电话两个可编辑项目。
- 新小程序不再提交 `landlordName`、`landlordPhone`。
- 前端 API 类型可以暂时保留兼容字段，避免破坏旧响应解析；页面不读取、不展示、不写入。
- 后端实体和 DTO 字段暂时保留，保证已有数据和旧客户端兼容，不执行数据库迁移。

## 官网改动

- 删除合作咨询区域的整块 HTML，包括介绍卡和咨询表单。
- 删除指向该区域的导航或按钮锚点。
- 删除只服务于咨询表单的 JavaScript 和无用 CSS。
- 全站移除“二房东”定位，改为盘源对接人和房源运营团队相关表达。
- 官网不新增替代咨询表单。

## 后端改动

- 用户可见异常提示、Swagger 描述、DisplayName、XML 注释和实体列说明使用“盘源对接人”。
- 权限规则保持不变：管理员可管理全部楼盘，盘源对接人只管理归属自己的楼盘。
- 保留 `SlLandlord`、`sl_landlord`、`isLandlord`、`landlordApplyStatus`、`LandlordName`、`LandlordPhone` 和 `/api/slLandlord/*`。
- 不修改数据库表名、字段名、路由、请求结构和响应结构。

## 不在范围内

- 不修改旧小程序 `ShenLe_MiniApp`。
- 不做数据库字段重命名或数据清理。
- 不改变盘源对接人的申请、审批、楼盘分配和写权限逻辑。
- 不为删除的官网咨询区增加新的表单或外部服务。

## 验证

- 新小程序生产源码和官网不再出现中文“房东”或“二房东”。
- 后端业务源码的用户可见中文和业务说明不再出现旧术语。
- 内部英文兼容标识继续存在且接口契约不变。
- 小程序术语扫描测试先失败再通过。
- `pnpm test`、`pnpm type-check`、`pnpm build:mp-weixin` 通过。
- 微信开发者工具编译无错误和警告。
- 后端相关测试和 `dotnet build .\ShenLe.sln --no-restore` 通过。
- 官网校验脚本通过，且咨询区和“二房东”文案均不存在。
