# 盘源对接人批量管理设计

## 目标

- 新小程序隐藏“我的”和普通用户申请页中的盘源对接人自助申请入口。
- 不删除、不禁用现有申请接口，旧版本仍可申请，管理端继续处理历史和旧版本产生的待审申请。
- 超级管理员可以一次选择多个用户设为盘源对接人。
- 超级管理员可以在某一位盘源对接人的视角下，一次新增或移除多个楼盘归属。
- 分配列表只展示未分配楼盘和已分配给当前目标用户的楼盘，绝不展示其他用户的楼盘。

## 自助申请入口

只修改新小程序展示层：

- `src/pages/admin/mine/index.vue` 删除申请、重新申请和审核中模块及其提交函数。
- `src/pages/common/apply/index.vue` 删除盘源对接人申请区域及对应状态加载、提交逻辑。
- 后端 `/api/slAccess/applyLandlord` 等现有契约保持原样。
- 管理端待审申请区保留，拒绝文案不再承诺用户可以在新版本重新申请。

## 批量设置盘源对接人

“直接设为盘源对接人”改为“批量设置”。弹层使用复选列表：

- 用户行显示昵称、账号角色和“已设置”状态。
- 已经是盘源对接人的用户可见但禁选，避免重复操作和状态不透明。
- 未设置用户可跨分页多选，底部固定显示“已选择 X 人”和“确认设置”。
- 后端用户列表补充 `isLandlord`，并新增事务接口 `/api/slLandlord/batchSetLandlord`。
- 批量接口对用户 Id 去重，复用 `EnsureLandlord`，重复提交保持幂等。
- 批量取消不纳入本轮，单条取消入口继续保留，避免误清空多人名下楼盘。

## 批量分配楼盘

每张盘源对接人卡片继续保留“分配楼盘”。进入弹层后：

- 顶部支持楼盘名称搜索和 `全部 / 未分配 / 已分配给他` 分段筛选。
- 楼盘行显示名称、楼栋数、房源数以及明确归属状态。
- 已归当前用户的楼盘默认选中并显示蓝色“已分配给此人”；未分配楼盘默认未选并显示灰色“未分配”。
- 点击整行切换最终状态，不再同时出现“分配”和“移除”两个互相冲突的按钮。
- 变更跨搜索和分页保留。底部固定显示“新增分配 X 个 · 移除 X 个”，无变更时保存按钮禁用。
- 保存成功后刷新弹层数据和外层“名下 X 个楼盘”。

归属仍建立在楼盘层级，楼盘下房源整体随楼盘归属。本轮不增加房源级归属，也不在该弹层展示空置、预定、已租等销控状态。

## 后端契约

新增：

- `POST /api/slLandlord/batchSetLandlord`
  - 输入：`userIds`。
  - 输出：实际处理人数。
- `GET /api/slCommunity/assignmentPage`
  - 输入：`ownerUserId`、`keyword`、`assignmentStatus`、分页参数。
  - 只返回 `OwnerId == null` 或 `OwnerId == ownerUserId` 的楼盘。
  - 输出包含 `isAssigned`、楼栋数和房源数。
- `POST /api/slCommunity/batchAssignOwner`
  - 输入：`ownerUserId`、`assignCommunityIds`、`unassignCommunityIds`。
  - 输出：新增和移除数量。

批量写入在同一事务内执行。分配时若楼盘已归其他用户，整批失败并返回冲突楼盘；移除时只允许移除目标用户自己的楼盘。已归目标用户的重复分配、已取消的重复移除按幂等无操作处理。

## 状态与并发

- 前端只提交用户实际切换过的增量，不用“当前页面所见结果”覆盖目标用户全部楼盘，避免分页导致误删。
- 后端是最终权限和并发边界；即使列表打开后归属被其他管理员改变，保存也不会覆盖其他用户。
- 提交期间禁用重复点击；失败时保留当前选择，方便管理员修正或刷新。

## 验证

- 新小程序两个申请入口均消失，管理端待审申请仍存在。
- 批量设置过滤重复 Id，已设置用户不可选，成功后列表立即更新。
- 分配列表只出现未分配和目标用户楼盘，状态、筛选和分页一致。
- 批量新增、批量移除、无变更、重复提交及并发冲突均有自动化测试。
- 通过前端测试、类型检查、微信构建、DevTools 编译、后端测试和构建后，上传 `0.4.6` 并部署后端。
